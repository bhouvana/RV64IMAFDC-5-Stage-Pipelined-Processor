An in-order 5-stage pipeline (Fetch → Decode → Execute → Memory → Writeback) with hardware forwarding, hazard detection, a real multi-cycle divider, full single- and double-precision floating point, a from-scratch RVC decoder, the 'A' (atomic) extension, M/S/U privilege with Sv32/Sv39 MMUs, real asynchronous interrupts, a hand-rolled SBI firmware, and a Linux-driver-compatible on-chip bus — checked against an independent instruction-set simulator and a real, unmodified Linux kernel image on a Verilator-backed model. Five stages, real interlocks

Separated by four pipeline registers (reg1–reg4), in the default 5-stage profile (a split-fetch 6-stage alternate is also available, elaboration-time swappable). Hazards are handled in hardware, not papered over in software: a forwarding unit resolves most RAW hazards in the same cycle (integer and float each get their own forwarding network), a hazard-detection unit stalls the one case forwarding can't fix (load-use), and control hazards flush speculatively-fetched instructions on a resolved branch, jump, trap, or interrupt.

Full RV64F/D, not a reduced subset

fadd/fsub/fmul/fdiv/fsqrt in both single (.s) and double (.d) precision, the fmadd/ fmsub/fnmsub/fnmadd fused multiply-add family (rounded once, not twice), sign-injection, min/max, comparisons, conversions, and a live fflags/frm — with full static and dynamic rounding-mode support. A separate float file gets its own full forwarding network from day one, not a stall-only placeholder.

FRegister.v
32×32 float register file, no x0-equivalent — every register is ordinary and forwardable.
FALU.v / FDivider.v / FSqrt.v
Combinational float ALU plus multi-cycle divide/sqrt units, verified against an exact-rational-arithmetic Python reference model.
FMADDUnit.v
Fused multiply-add — the full unrounded product is aligned against the addend and rounded exactly once.
FForward.v
A dedicated float forwarding network (three read ports, for the FMA family's three operands) — not bolted onto the integer one.

A real bus, Linux-compatible peripherals, real interrupts

Data memory sits behind a classic Wishbone-style handshake, alongside a real 8-register ns16550a-compatible UART and a real RISC-V CLINT — both redesigned specifically so a real, unmodified Linux kernel needs no driver patch to talk to either.

WbDecoder.v / RamWishboneAdapter.v
A parameterized address decoder/mux, plus a thin bus wrapper around the existing memory that changes not one line of the already-verified module.
Uart.v
A real 8-register ns16550a map (RBR/THR, IER, IIR/FCR, LCR, MCR, LSR, MSR, SCR, DLAB-gated) — a DT compatible="ns16550a" string is enough for Linux's own driver.
Timer.v
A real RISC-V CLINT: msip/mtimecmp/mtime at the exact byte offsets Linux's own timer-clint.c hardcodes.
Interrupt redirect
Real spec priority MEI > MSI > MTI > SSI > STI, including a software-synthesized supervisor interrupt path for a real kernel scheduler tick.

RVC, atomics, MMU, SBI — and a real Linux boot attempt

A from-scratch RVC (compressed instruction) decoder and 'A' (atomic) extension implementation, a full M/S/U privilege architecture with independent Sv32 and Sv39 MMUs, and a hand-rolled M-mode SBI firmware — built because a real, unmodified riscv64 Linux kernel Image needed every one of them. Verilator-backed for real throughput (~1.4M cycles/sec), the kernel now executes correctly through its own compressed-instruction-heavy entry sequence and a real amoadd.w hart-check, 200 million+ cycles with zero crashes — the deepest real-kernel execution this core has ever achieved.

CompressedExpander.v
Real RVC decode, the full standard quadrant table — expands every compressed instruction to its bit-exact standard 32-bit encoding before any other stage sees it.
2-phase AMO interlock
lr/sc/amo*, a real read-modify-write MEM-stage sequence, independent of the existing load/store interlock.
Tlb.v/Ptw.v + Tlb39.v/Ptw39.v
Two genuinely separate MMU implementations — Sv32 for RV32, a from-scratch 3-level Sv39 walker for RV64.
sim/firmware/
A hand-rolled M-mode SBI firmware (legacy v0.1 and real v0.2+) plus a hand-rolled device-tree-blob emitter — no dtc dependency.

Verifying an unpredictably-timed asynchronous event against a sequential reference simulator, without real cycle-accurate co-simulation, turned out to be the hardest part of this whole project — see docs/adr/0020-soc-integration.md for the full story, including a real CSR.v correctness bug that only became possible once the interrupt redirect made trap entry independent of what's executing, and wasn't caught until a 100-seed random sweep.

A second core: out-of-order, dynamically scheduled

design/OOOCore.v is a genuinely new top-level module, not a modification of riscvpipeline.v — register renaming, a physical register file, per-unit reservation stations, a reorder buffer, a load/store queue, Tomasulo-style Common-Data-Bus scheduling, speculative branch/jalr execution, and dual-issue dispatch. design/HeteroSoC.v runs it alongside riscvpipeline.v at the same time — a real heterogeneous dual-core SoC, two different microarchitectures sharing one bus, not two copies of the same core. Closed as Generation 6 (docs/adr/0058): 135/135 directed suite at closure, every scope item the roadmap named (renaming, PRF, reservation stations, ROB, LSQ, Tomasulo, speculation, dual-issue) done and verified.

ReservationStation.v
One per functional unit (ALU/DIV/FALU/FDIV) — operands dispatch the moment they're ready, not in program order.
ReorderBuffer.v
Multi-ported completion, in-order retirement, precise exceptions.
LoadStoreQueue.v
Memory-ordering enforcement independent of the ALU pipeline's own out-of-order completion.
HeteroSoC.v
Both cores, one bus — a real heterogeneous dual-core SoC, not a hypothetical.

Generation 7: ratified ISA extensions, same shared decode path

Five pillars planned (docs/adr/0059), each a real RISC-V extension wired into the out-of-order core's existing reservation stations, ROB, and CDB — zero new ports per extension, zero standalone processor per extension. Three closed so far.

B — Bit-Manipulation closed
Full ratified Zba+Zbb+Zbs, ~39 mnemonics incl. RV64-only word variants. 137/137 directed suite, constrained-random clean across scalar/OoO × XLEN 32/64 × Sv32/Sv39. docs/adr/0060.
V — Vector Processing closed
Vector register file, vtype/vl config, a per-element vector ALU + load/store unit, full-LMUL crack sequencer. 146/146 directed suite. docs/adr/0065/0066.
K — Cryptography closed
Full ratified Zkn — AES encrypt/decrypt/key-schedule, SHA-256/512, carry-less multiply, 22 mnemonics. FIPS-197 KAT verified end-to-end. 152/152 directed suite, real clmul benchmark (7 cycles HW vs. 12 scalar). docs/adr/0067.
H — Hypervisor, P — Packed-SIMD not started
H needs real S-mode wired into OOOCore.v first (currently sret is hardwired off). P is an unratified draft extension, will be labeled as such throughout.

Real bugs found along the way, not just decode gaps: RV64-only word-variant decode holes only --xlen 64 random testing caught (B); two independent pre-existing slli.uw bugs in ALU.v/ImmGen.v found by K's own cross-check, unrelated to K itself but fixed anyway; a cross-namespace CDB tag collision and a wrong PRF dispatch-readiness port found by V's own closure benchmark. See docs/adr/0058 through 0067 for the full story.

Verification, not vibes

Directed tests catch what you thought to test for. This core is also cross-checked against sim/tools/iss.py, an independent instruction-set simulator with no shared code path to the RTL — constrained-random programs run on both, and any divergence is a real bug. That process alone has found and fixed dozens of RTL bugs that no directed test caught.

Directed suite
152 self-checking tests, both cores — ISA coverage, forwarding, hazards, float arithmetic, CSR/exception handling, branch resolution, bus/UART/timer behavior, interrupt redirect correctness, out-of-order renaming/RS/ROB/LSQ/speculation, and every B/V/K instruction.
Random cross-check
1000+ constrained-random programs matched bit-for-bit against the independent ISS reference model — including an opt-in mode that fires a real, unpredictably-timed interrupt mid-program, and an --ooo mode targeting the out-of-order core.
RTL assertions
4 embedded invariants (forwarding-select legality, stall/flush consistency, x0 hard-wired to zero, store-forwarding correctness) — verified to actually fire by deliberately reintroducing the bug each one guards against.
Functional coverage
Per-opcode / per-branch-direction counters closed a real gap: bne was untested by any directed program until coverage caught it.
